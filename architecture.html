System Architecture

One model, one bundle, every surface.

How the Zen Analytics Workbench fits together — from the desktop canvas and the coding-agent sidecar, down through a single Node backend and its engines, to the one model you view through four lenses. Everything is local-first; source and data never leave the machine.

Key flows — how it plays together

FLOW 01
Vibecoding, grounded
The agent codes with awareness of your repo's real structure, stack & risks — before it writes the next line.
Claude Code → MCP → sidecar/core → code-intel → your repo → grounding back
FLOW 02
One trace, both layers
A single OpenTelemetry import lights up the infrastructure twin and the code-graph latency heat — a span carries both service.name and code.function.
OTel trace → codeintel/telemetry → infra nodes + call-graph overlay
FLOW 03
Model → lenses
You edit one model; flipping a lens re-draws it — the model underneath never changes.
model → Logical · Physical · Network · Code
FLOW 04
Code ↔ infra tie-in
Assign a module to a canvas node and hop either way — from a node see its code, from a symbol see its node & measured latency.
Code lens ⇄ codeLinks ⇄ architecture node
Local-first — runs on your laptop; source & data stay on the machine. One bundle — a modular monolith (esbuild), shipped in the app and as the sidecar. Extensible — five open registries; every language, telemetry source & correlator is a plugin.
